# Interview Behavior Video Analysis

FastAPI-MVP для анализа **наблюдаемых** признаков поведения человека в видео интервью или видеоответе. Система отдельно хранит алгоритмические измерения и интерпретацию LLM. Она не определяет психотип, не ставит диагнозы и не делает выводов о правдивости человека.

## Что анализируется локально

`VideoAnalyzer` проходит видеоряд с частотой `VIDEO_SAMPLE_FPS` (по умолчанию 5 кадров/с), сохраняя временную последовательность. MediaPipe Face Mesh и OpenCV используются для:

- доли кадров с лицом;
- морганий и длительности закрытия глаз по eye aspect ratio;
- приблизительного направления взгляда по положению радужки и изменений направления;
- улыбкоподобной геометрии, открытия рта и движения бровей;
- изменений конфигурации ориентиров лица;
- yaw, pitch, roll головы через `solvePnP` и выраженных изменений позы.

Если MediaPipe не импортируется, приложение продолжает работать в ограниченном режиме и определяет только наличие лица через OpenCV Haar Cascade.

`AudioAnalyzer` извлекает моно WAV 16 кГц через FFmpeg, поставляемый `imageio-ffmpeg`, и локально вычисляет длительность, RMS, долю низкоэнергетических окон и оценочное число переходов к паузам.

## OpenAI

При наличии `OPENAI_API_KEY` официальный Python SDK выполняет:

1. транскрипцию через `client.audio.transcriptions.create`; модель задаёт `OPENAI_TRANSCRIPTION_MODEL`, по умолчанию `whisper-1`, чтобы получить `verbose_json` с временными сегментами;
2. смысловую сегментацию интервью на пары «вопрос/инструкция/кейс/изменение условий → ответ» через Responses API; модель задаёт `OPENAI_SEGMENTATION_MODEL` (по умолчанию значение `OPENAI_MODEL`);
3. структурированный анализ нормализованных видео- и речевых данных через Responses API. Сырые видеокадры в LLM не отправляются.

Модель смысловой сегментации выбирает только ID исходных сегментов транскрипции. Поля `question_start`, `question_end`, `answer_start` и `answer_end` берутся сервером непосредственно из timestamps этих сегментов, а не рассчитываются по длине текста. Полная транскрипция остаётся в `speech.transcript`, исходные сегменты — в `speech.segments`, дополнительная разметка — в `speech.qa_segmentation`.

Без ключа загрузка интерфейса, `/health`, видеоанализ и локальные аудиометрики остаются доступны. В ответе API статусы транскрипции и LLM будут `unavailable`.

## Установка и запуск

Требуется Python 3.11 или 3.12.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
python run.py
```

Откройте <http://127.0.0.1:8000>. Документация API: <http://127.0.0.1:8000/docs>.
# Альтернативный запуск напрямую через Uvicorn:
python -m uvicorn app.main:app --reload --port 8000


Для транскрипции и LLM-анализа добавьте в `.env` переменную `OPENAI_API_KEY`. Ключ не передаётся клиентскому JavaScript.

## API

- `GET /` — веб-интерфейс;
- `GET /health` — состояние и доступные возможности;
- `POST /api/analyze` — multipart-загрузка в поле `file`;
- `GET /docs` — Swagger UI.

Сервисы можно импортировать независимо от HTTP-слоя:

```python
from app.services import VideoAnalyzer, AudioAnalyzer, InterviewSegmenter, LLMAnalyzer
```

Каждый успешный вызов `POST /api/analyze` создаёт отдельную неизменяемую версию в `results/<имя-видео>_<дата-и-время>/`. В ней сохраняются полный `result.json` и человекочитаемый `summary.md`. Путь версии возвращается в поле `saved_result_path`. Если в результате присутствует `timebase_mapping`, рядом автоматически создаются `timebase_mapping.json` и, для табличного mapping, `timebase_mapping.csv`.

## Архив видео и экранного анализа

Новые записи в `results` содержат исходное `source.<расширение>`, полный `result.json`, `summary.md` и `metadata.json` с UUID и датой анализа. Запись появляется в архиве после завершения сохранения всех файлов. Исходное видео копируется без перекодирования.

В блоке «Сохранённые анализы» нажмите «Открыть». Все разделы восстанавливаются существующими функциями интерфейса. Откройте несколько записей для сравнения; можно совместить их с результатами новых загрузок. Состав и порядок наборов сравнения отдельно не сохраняются.

Просмотр архива не запускает MediaPipe, распознавание речи, сегментацию или LLM и не обращается к внешним API. Локальные маршруты: `GET /api/archive`, `GET /api/archive/{id}`, `GET /api/archive/{id}/video`.

Старые результаты открываются без изменения файлов. При отсутствии исходного видео показывается предупреждение. Если новое сохранение не удалось, готовый результат и выбранное видео остаются на текущей странице, а ошибка архива отображается отдельно. После закрытия страницы несохранённый результат недоступен.

## Подключаемая авторизация архива

Модуль `app/auth` подключается одним вызовом `install_auth(app)` в `app/main.py`. Он защищает только `/api/archive` и все вложенные маршруты, включая JSON и видео с перемоткой. Анализ новых видео не требует входа и работает как прежде. Отдельной страницы админки, базы пользователей и ролей нет.

Первичная настройка из корня проекта:

```powershell
python -m pip install -r requirements.txt
python -m app.auth.setup
python run.py
```

Команда настройки спрашивает логин, пароль и подтверждение (пароль не отображается; минимум 12 символов). В `.env` сохраняются только логин и хеш Argon2id с солью; `AUTH_ENABLED` устанавливается в `true`. Остальные настройки сохраняются. Затем перезапустите приложение и войдите через небольшой блок в разделе «Сохранённые анализы» на главной странице. Повторный запуск команды позволяет изменить учётные данные; после перезапуска прежние сессии недействительны.

Для отключения установите `AUTH_ENABLED=false` в `.env` и перезапустите приложение. Блок входа скрывается, а архив работает без авторизации в прежнем режиме. Если параметр отсутствует, применяется этот же совместимый режим. При `AUTH_ENABLED=true` без корректного хеша архив остаётся закрытым.

Сессии хранятся в памяти одного серверного процесса, отзываются при выходе и теряются при перезапуске. Срок бездействия — 30 минут, предельная длительность — 8 часов. Пароль и идентификатор сессии не хранятся в JavaScript/localStorage. Cookie имеет `HttpOnly` и `SameSite=Strict`. Для локального HTTP оставьте `AUTH_COOKIE_SECURE=false`; для доступа через HTTPS установите `AUTH_COOKIE_SECURE=true`. Передачу пароля вне локального компьютера следует выполнять только через HTTPS. Доступ к файлам `.env` и `results` на самом компьютере определяется правами ОС.

При выходе или истечении сессии открытые из архива карточки убираются; новые результаты остаются на странице. Повторная обработка или вызовы OpenAI при входе/просмотре не выполняются.

## Проверки авторизации и архива

Дополнительная браузерная проверка восстановления экрана: `node tests/archive_ui.cjs` (требуется Playwright). Она использует существующий JSON и MP4 из этого проекта, перехватывает все HTTP-запросы локально и не запускает реальный анализ. При использовании установленного Edge задайте `UI_BROWSER_CHANNEL=msedge`. Проверяются все экранные разделы, графики, смешанное сравнение, воспроизведение и обработка ошибки сохранения.

Браузерную проверку запускайте дважды: с `UI_AUTH_ENABLED=false` и с `UI_AUTH_ENABLED=true`. Браузерный тест проверяет интерфейс с локальными заглушками; реальные серверные проверки cookie, отзыва сессии, CSRF, ограничения попыток и защиты архивных маршрутов выполняются в `tests/test_auth.py` через TestClient.

```powershell
python -m pytest -q
```

## Смысловой конспект встречи

Для новых анализов после полной транскрипции отображается «Краткое содержание встречи»:
5–8 предложений, принятые решения, задачи и открытые вопросы. Модуль
`app/services/meeting_summary.py` использует только готовую транскрипцию и существующие
`OPENAI_API_KEY`/`OPENAI_MODEL`. Это отдельный вызов OpenAI независимо от поведенческого
LLM-анализа. Дополнительные настройки не требуются.

Решения и открытые вопросы извлекаются дословно; для задач проверяется наличие цитаты
с поручением, а ответственный и срок допускаются только из неё. Эти проверки отсекают
отсутствующие в тексте сведения, но не заменяют проверку смысловой корректности человеком.
Если соответствующих пунктов нет, интерфейс и Markdown показывают «Не выявлены».
При отсутствии транскрипции/ключа конспект недоступен; при ошибке API или проверки цитат
получает статус `failed`, не препятствуя сохранению основного анализа.

Результат находится в необязательном поле `meeting_summary` файла `result.json`, а также
в `summary.md` после транскрипции и перед Q&A. Старые записи открываются без изменения
и без генерации конспекта: отображается сообщение, что он не сформирован.
Новая функция добавляет время обработки и отдельную стоимость API для новых анализов.

Проверки без внешних AI-вызовов: `python -B -m pytest -q -p no:cacheprovider`,
`node tests/meeting_summary_ui.cjs`, `node tests/cloud_ui.cjs`.

## Ограничения

### Импорт видео из облака (PRO, этап 1)

На главной странице добавлены поле «Ссылка на видеозапись» и кнопка «Добавить из облака».
Поддерживаются прямые HTTP/HTTPS-ссылки на MP4/WebM и публичные файлы Google Drive
в формате `/file/d/ID/view`, `/open?id=ID` или `/uc?id=ID`. После скачивания автоматически
выполняется тот же конвейер, что и для локального файла. API: `POST /api/analyze-url`
с JSON `{"url":"https://example.com/meeting.mp4"}`. Формат ответа совпадает с `/api/analyze`.

Размер ограничен существующим `MAX_UPLOAD_MB` (по умолчанию 500 МБ). Загрузчик проверяет
HTTP-статус, заявленный и фактический размер, MIME и сигнатуру MP4/WebM; окончательная
читаемость видео проверяется существующим видеоанализатором. Разрешены стандартные порты
80/443, до пяти переходов (включая подтверждение Drive), сетевое ожидание до 15 секунд
за операцию и общий бюджет скачивания 120 секунд с проверкой между чтениями.
Системное разрешение DNS может дополнительно занять время. Каждый адрес и редирект
проверяется на публичность; соединение закрепляется за проверенным IP, с сохранением
проверки TLS-имени. Прокси из окружения не используются. Перенаправление HTTPS → HTTP запрещено.

Для Drive поддержано публичное скачивание и HTML-форма подтверждения крупных файлов.
Приватные файлы, OAuth, вход в аккаунт, cookies, CAPTCHA и обход запрета скачивания не
поддерживаются. Изменение формата страниц Drive может потребовать обновления адаптера.
Обычные веб-страницы вместо видео отклоняются. При ошибке остаётся обычная загрузка файла.

Обработка синхронная: оставьте страницу открытой до ответа. Прогресс пока общий,
без фоновых заданий и дедупликации. Новые результаты и видео сохраняются существующим
архивом; источник URL отдельно пока не записывается. Карточка облачного результата
показывает анализ; сохранённое видео доступно через архив после обновления страницы
и, если защита включена, входа в архив. Авторизация и настройки не изменены.

Безопасные автоматические проверки: `python -B -m pytest -q -p no:cacheprovider`
и `node tests/cloud_ui.cjs`. Новые тесты используют синтетические байты и заглушки
скачивания/AI; реальные видеозаписи и платные запросы не нужны. JS-проверка проверяет
обработчик формы без браузера. Реальный импорт, включая Google Drive, в этих тестах
не проверяется. Нажатие кнопки в работающем приложении запускает настоящий анализ и
при настроенном ключе — существующие обращения к OpenAI.

Геометрические пороги MVP приблизительны и чувствительны к освещению, очкам, повороту лица, разрешению и частоте выборки. Направление взгляда означает геометрию глаз на изображении, а не объект внимания. Энергетические окна аудио не равны точному voice activity detection и могут включать музыку или шум. Результаты требуют проверки человеком и не предназначены для автоматических кадровых решений.
